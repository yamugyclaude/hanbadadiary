## 2. 핵심 동작 흐름

### 2-1. 장비 추가/수정/사진/관리내역
1. 사진은 먼저 Storage에 업로드 → URL 확보 (`_migrateEquipPhotos`)
2. 로컬(localStorage) 즉시 반영
3. **바뀐 장비 1개만** DB에 저장 (`_syncEquipmentCloud(item)` → 행 `eq_<id>` upsert)
   - 항목에는 **반드시 `cat` 포함** (안 넣으면 아래 3장의 사고 재발)

### 2-2. 삭제
- DB 행 `eq_<id>` 삭제(`_deleteEquipCloud`) + Storage 사진 파일 삭제(`deleteEquipPhotos`)

### 2-3. 불러오기 (`loadEquipmentFromCloud`)
- `id=like.eq_%` 행을 모두 조회 → `v15.cat` 기준으로 카테고리별 재구성
- `eq_` 행이 하나도 없고 옛 `equipment` 단일행만 있으면 → **1회 자동 이전(마이그레이션)** 후 사용

### 2-4. 기본 장비 시드 (`initEquipmentDefault`)
- 비어 있는 카테고리에만 기본 목록을 채운다.
- 채울 때 **`cat` 포함 + 고정 ID(`eq_def_<cat>_<name>`)** 사용
  → 여러 기기/여러 번 로드돼도 같은 행에 덮어써져 **중복이 쌓이지 않음**

### 2-5. 실시간(Realtime)
- `eq_` 행의 추가/수정/삭제 이벤트를 받아 해당 장비 1개만 화면 갱신 → 기기 간 자동 반영

## 3. 2026-06-25에 있었던 사고와 해결 (중요)

### 증상
- 장비관리 탭에 **어제 추가한 1개만** 보이고 원래 데이터가 사라진 것처럼 보임.

### 진짜 원인
- 기본 장비를 만들 때(`initEquipmentDefault`) **`cat`을 빠뜨려** 저장됨.
- 불러올 때 코드가 **`cat` 없는 항목은 버림** → 화면에 안 뜸.
- 화면상 비어 보이니 **매 로드마다 기본값을 새 ID로 또 생성** → DB에 카테고리 빈 행이 **380개까지 누적**.
- 카테고리가 제대로 들어간 항목은 "어제 수동 추가한 LD" 1개뿐 → **그 1개만** 보였던 것.
- ※ 진짜 원본(음향35·무대17·특효6·기타5)은 옛 단일행 `equipment`에 **안전하게 보존**돼 있었음(마이그레이션이 쓰레기 행 때문에 안 돌아 손 안 탐).

### 해결
1. **코드 수정**: `initEquipmentDefault`가 기본 장비에 `cat` 포함 + 고정 ID 사용 → 누락/중복 차단. (v0622-54)
2. **데이터 정리(1회)**: 원본 63개 + LD 1개 = **64개를 `cat` 붙여 `eq_` 행으로 재정비**(음향36·무대17·특효6·기타5), **빈 `cat` 쓰레기 379개 삭제**, 옛 단일행은 백업 보존.

### 교훈 / 체크포인트
- 장비 항목을 클라우드에 저장하는 **모든 경로는 반드시 `cat`을 포함**해야 한다.
- 기본값/반복 생성되는 데이터는 **고정(결정적) ID**를 써야 기기 간 중복이 안 생긴다.
- "데이터가 사라졌다"는 신고가 오면, **먼저 DB를 직접 조회**해 실제로 없는지 확인한다(대개 화면/동기화 문제이고 원본은 살아있음).
