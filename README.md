## 🏢 잭슨컴퍼니 조직

여기는 **잭슨컴퍼니**입니다. 조직 구조는:

```
          📊 사장
           │
           ├─ 🗂️ 비서 (Claude 메인) — 조율·일임·진행 추적
           │
           └─ 실장들 (사장 직보)
              ├─ 📋 기획실장 (planner) — 계획 수립
              ├─ 🛠️ 실행실장 (builder) — 코딩·배포
              ├─ 🔍 정보실장 (research-scout) — 웹 조사
              └─ 🔎 감사실장 (auditor) — 독립 검증

💰 감시실장 (token-watch) — 토큰 효율 감시 (보조)
```

**역할 분리**:
- 비서(메인 Claude)는 **일을 직접 다 하지 않음** → 실장들에게 **일임**
- 실장들은 각자 **사장에게 직보**
- 감사실장은 **독립적 검증** (비서 지시 안 받음)

```

비서: "🔎 감사실장에게 검증을 요청합니다"
```

## ❓ FAQ

### Q1: 라이브 사이트가 업데이트 안 되는데?
**A**: 3가지 확인
1. `git push origin main` 완료했나?
2. GitHub Actions 빌드 성공했나? (Actions 탭 확인)
3. 브라우저 캐시 무시 새로고침: `Ctrl+Shift+R`

### Q2: 개발할 때 로컬에서 어떻게 테스트하나?
**A**: `index.html`을 브라우저에서 열기만 하면 됨
- Windows: 파일 탐색기 → index.html 우클릭 → "열기" → 브라우저
- Mac: Finder → index.html → 더블클릭
- 또는 로컬 서버: `python3 -m http.server 8000`

### Q3: Supabase는 뭐고 어디서 쓰나?
**A**: 데이터 저장소
- 행사 정보, 차량, 장비, 알바 정보 저장
- REST API로 통신
- 수정·삭제 시 암호(`2375`) 필요

### Q4: 이 프로젝트의 구조는 어떻게 되나?
**A**: 단일파일 SPA
```
hanbadadiary/
├── index.html (10,000줄 이상)
│   ├── <style> (CSS 포함)
│   ├── <script> (JavaScript 포함)
│   └── <body> (HTML 구조)
├── .github/
│   └── workflows/
│       └── deploy.yml (배포 자동화)
└── docs/
    └── 장비관리_데이터구조.md (데이터 구조 설명)
```

### Q5: 버그 찾으면 뭘 해야 하나?
**A**: 사장님께 보고
- 뭐가 잘못되었나 설명
- 재현 방법 (스텝 바이 스텝)
- 스크린샷 첨부 (선택)

### Q6: 새 기능 제안이 있으면?
**A**: 사장님께 말씀
- 기능이 뭔지 설명
- 왜 필요한지 설명 (사용자 관점)
- 기획실장이 상세 계획 수립

### Q7: 코드 수정 후 커밋 메시지는 어떻게 쓰나?
**A**: 한눈에 알 수 있게
- ❌ "fix" / "update"
- ✅ "스피커브랜드 5개 모델 추가 및 다중 선택 지원"
- 기술 세부사항은 커밋 본문에

### Q8: 개발 브랜치는 따로 있나?
**A**: 현재는 main에 직접 커밋하는 방식으로 운영 중
- 사장 지시를 받으면 **main에서 바로 작업**
- 커밋 후 **바로 푸시**
- 자동 배포됨
